# 提交完成与紧凑编辑（1.13.3／35）

## 用户行为

- “设置 → 提交作业 → 提交后自动完成作业”默认开启；设置保存入口固定在窗口底部。
- 应用提交和终端提交均须确认进入个人远端的指定分支，才可完成对应作业。本地未推送、远端待核验、同步、合并和老师上游提交不触发完成。
- 明确关联优先。无关联时，使用已有唯一文件关联或独立作业目录。默认识别 `assignment-X/README.md` 为题目，`assignment-X/assignment.md` 为答案；`Project-X` 支持代码文件。不按标题猜测，共用目录或根目录材料保持待关联。其他独立目录及明确关联继续支持。
- 首次核验建立基线，不补处理历史；历史改写、恢复备份或重新开启功能会建立新基线。手动关联历史提交是单独的明确操作。
- 任务正在编辑时暂缓完成；结束编辑后读取最新任务，必要时重新核验。成功显示“已完成 X 项”，原生工具栏提供撤销；提交依据显示在任务详情及提交记录。
- 撤销只恢复完成状态，保留刚保存的文字。相同提交不会重新完成同一任务；未来新提交可重新判断。周期后续项只生成一次。

## 数据与并发

`AMSubmissionCompletion.inc` 统一匹配和应用决定；使用原任务完成逻辑处理子任务、时间戳及周期项。任务、决定、系列与日历通过现有可恢复事务保存，写入失败不报告成功。

可选 `completionEvidence`、提交记录的完成决定及关联版本随原备份保存；没有这些字段的旧任务和记录继续可读。恢复保留依据及撤销决定，冻结导入记录的自动完成资格并清空核验基线。`submission-automation.plist` 仅存开关、启用批次和个人分支的远端基线，不保存凭据。

后台核验合并最新撤销与关联状态，不能覆盖用户刚修改的关联。远端读取沿用队列和 Git 资源锁，后台重新核验限频，不推送、不调用模型。

## 界面与提醒

普通编辑默认约720×640、最小560×500；680×620及以上普通编辑无外层溢出。日期与重复在宽窗口并排，小窗口自动换行。备注80–120点，长备注内部滚动；保存与校验固定在底部。复杂重复和来源证据展开仍按实际内容提供滚动。

任务完成时立即移除已排队的提醒及已送达通知。旧注册回调迟到也再次取消；启动时清理遗留通知。前台展示前按最新任务状态检查，兼容缺少 `taskID` 的旧稳定标识。恢复待完成后重新安排未来提醒。

## 验证边界

临时 Git 仓库和隔离 AppKit 回归覆盖推送、离线、历史改写、唯一／歧义匹配、来源排除、备份、事务失败、并发关联、撤销、编辑保护及通知竞态。测试只用合成材料和假通知，不读取真实课程或密钥、不请求模型、不捕获屏幕。

几何与行为回归通过不等于真实窗口外观验收；独立编号预览由用户核对后再正式发布。macOS旧版本实机及系统实际通知送达仍需实机验证；保留临时签名与未经Apple公证说明。
