# 增量检查与后台操作

本轮目标为 1.13.2 / 构建 34。正式更新须在隔离预览的实际窗口验收后发布。

## 检查记录

- 每次检查仍核验老师默认分支和读取权限，并获取最新提交。来源、分支、版本和规则条件相同时复用整批结果；有改动时仅读取或分析变化的材料。
- `scan-cache.plist` 保存文档快照、本机识别结果、日期依据和模型完成记录；空结果同样是有效完成。兼容已有 v9 识别缓存。
- 规则与模型完成记录分开。更新规则或课程模板会更新本机结果；模型、摘要提示版本变化不自动重发旧材料。主动重新分析只处理用户选择的文件。
- 相对日期依据按文件、行、时区和分支缓存；无关提交不重查，历史改写或分支变化会重新核验。链接附件仍按当前文档快照重新关联。
- 每份成功材料都保存检查点。写入失败明确返回错误；失败、取消和无效模型结果不推进模型完成标记。并行保存仅合并本次会话修改的键，避免旧快照覆盖新结果。

## 审核决定

- 删除操作只影响待审核建议，不删除已加入的任务。原文证据与附件指纹决定删除版本，模型改写标题或无关提交不使它重新出现。
- 删除决定和来源快照先原子写入 `review-decisions.plist`，再更新列表、选择和计数；保存失败保留原条目。
- 提供单项、批量、右键及列表聚焦时的 Delete，文本编辑仍保留正常删除。支持撤销，以及“已删除”筛选中的恢复。
- 来源或附件变化后可作为新版本提示；保存前再次检查当前来源和删除状态，重复确认仍按来源身份更新已有任务。

## 操作与草稿

- 后台任务具有排队、执行、完成、失败及取消状态；同一请求合并。模型服务默认单并发，自动识别按文档释放课程操作通道，手动请求优先于尚未开始的自动工作。
- 文件预览与本机检查只等待 Git 写入通道，不等待整批模型分析；写入期间请求可入队。排队取消不执行请求，批量取消先标记整个批次再恢复调度。
- 请求保留发起时的课程、材料、设置和选择。执行前重新核验课程关联与来源；结果不会写入后来切换的课程，审核草稿保留期间结果暂存。
- 窗口菜单展示目标、阶段、等待时间及取消入口。退出可等待或取消尚未开始的操作；队列不写入磁盘，重启不恢复已排队的发送。提交和推送仍需原有明确确认。
- 未保存判断比较当前有效值和初始化或成功保存基线。预填、聚焦、同值回调、检测模型元数据、进度和布局变化不算编辑；改回原值恢复为未修改。保存失败继续保留草稿。

## 原生控件与验证边界

- 今日／本周、日历任务状态、课程分区使用页面工具栏中的标准分段控件，控件复用并提供完整溢出菜单。macOS 27 区分导航与值选择角色，旧 SDK / 系统按公开可用 API 回退。
- 日历不再保存提前混合、已经解析为固定外观的系统颜色。周末使用中性浅灰、假日使用淡蓝，深色外观自动对应；选择与悬停作为独立覆盖层绘制，任务条使用平整底色。颜色回归覆盖在深色环境创建后切回浅色的既有格子及文字对比度。
- 回归使用模拟材料、临时 Git 仓库、回环模型服务及隔离窗口；没有读取真实 Gemini 密钥，也没有发送私人课程材料。
- 控件、存储、请求次数及交互测试不代表玻璃外观验收。浅深外观、窗口激活状态及辅助显示选项仍以用户提供的实际窗口截图核对；没有进行屏幕捕获。
