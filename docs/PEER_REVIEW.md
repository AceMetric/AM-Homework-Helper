# 同学作业与评分参考排名

## 查看作答

在课程“更多 → 同学作业…”选择老师来源与作业目录。应用通过当前账户读取可访问的 fork，支持分页、刷新与取消；显示查询时间和覆盖范围。可见仓库数不是全班人数。

“发现作答”表示在该作业范围发现相对老师共同版本的文件改动，不代表老师确认收件。“未发现作答”不等于未提交；无法访问、文件列表不完整或关联不明确时保留待核验状态。只更新老师内容或修改其他作业不会算作本次作答。

选择同学后核验版本，选择文件后读取正文。宽窗口分为同学、文件和预览三栏，窄窗口逐级查看。Markdown、图片、PDF 均固定到所示提交；可在 GitHub 打开原位置。不克隆或写入同学仓库，普通浏览不发送模型请求。切换账户后隔离本机缓存。

## 关联评价

“关联老师评价…”接受评价文本文件、具体 GitHub 评论或评审链接。应用显示作者、原位置及对应解答版本；用户核对是哪位同学、哪份作业、哪版解答后确认。多人评价文件可选中对应原文，不能只凭用户名或目录猜测。

有明确老师分数时同时核对得分与满分。只有评语时选择“老师只有评语，没有数值评分”，再准备题目及统一标准。评语语气不会直接变成老师分数。评价更新或对应版本不符时，旧记录保留在历史，不继续作为当前有效分数。

“关联已有LLM评分…”还需填写原模型、评价批次，并确认采用当前统一标准；结果标注为外部LLM记录。评价批次可单独筛选，不要求重新调用原模型。

## 补齐评分

1. 在“检查材料…”添加题目、要求或参考材料。PDF确认页码，Markdown图片单独确认添加；材料只用于检查，不进入提交文件清单。
2. 确认本份作业统一的百分制标准。可手动编辑维度和分值，也可明确请求模型生成草案；草案须再次确认后使用。
3. 选择同学、模型和请求上限，默认4次。再次核对所示版本的题目、完整作答、配图和老师评语后才发送。
4. 本地模型不上传；云端页面明确显示将发送的材料。标准生成、兼容请求、重试及续查均计数，达到上限停止；继续时复用有效评分，仅处理尚未完成部分。

评分必须提供各维度分数、扣分理由和可核验文件依据；不能执行同学代码。缺少题目、引用图缺失、关键二进制不支持或老师评语与作答冲突时保留“材料不足／待核验”，不把缺少材料当作学生未完成。某份失败不会丢掉其他已保存结果。

本地 JSON 约束不受服务支持时，只在确认的次数上限内兼容一次，并缓存服务能力；不放宽原文、分项合计或范围校验。云端错误不自动重放。取消不再安排下一次请求。

## 排名与保存

优先级：可核验老师分数 → 参考老师评语的新LLM评分 → 同一比较条件的已有LLM分数。界面逐项标记来源；老师与LLM同时存在时标明“混合来源”。按得分÷满分排列，保留原始分数，同分采用1、1、3名次。缺分不当作零分。

LLM分数绑定作答、题目、评价、统一标准、模型及提示词版本。作业范围外被明确引用的图片也保留来源版本；普通无关提交不会仅因全局提交号变化让相同作答失效。修改比较条件后旧分数仍可查看，不能混进当前批次。评分仅在本机保存，不写入任何课程仓库。

备份只包含个人用时和评分设置，不包含同学作答、远端预览缓存或密钥。老师评价关联和评分历史保存于本机，分享诊断或备份前仍应自行核对内容。

实现中的GitHub评审读取遵循官方[评审接口](https://docs.github.com/en/rest/pulls/reviews)与[行内评审评论接口](https://docs.github.com/en/rest/pulls/comments)，仅使用读取操作。
